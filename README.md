## 🎯 参赛主线与系统定位 (Core Mission)

本项目紧扣竞赛核心主赛道——**「注册会计师审计、数智审计与舞弊穿透 (AuditMind)」**，严格遵循《中国注册会计师审计准则第1141号——财务报表审计中与舞弊相关的责任》(CSA 1141) 与《企业会计准则》(CAS 14、CAS 1、CAS 36)，针对资本市场“跨期时序倒挂”、“伪造单据与虚增存款”及“体外资金自循环”等新型高隐蔽舞弊，打造从异构业财数据解析到穿透式审计底稿生成的完整工程闭环：

```
[企业财务总账 / Excel记账凭证 / 增值税发票清单 / 银行流水明细]
                           │
                           ▼
[确定性审计算子矩阵] ──► 借贷试算平衡、三单时序倒挂比对、Beneish M-Score 8因子操纵指数
                           │ (注入只读客观事实切片，100% 精确数学运算，根除大模型计算幻觉)
                           ▼
[DeepSeek 准则研判] ──► 对齐 CAS 14(新收入)、CAS 1(存货)、CAS 36(关联方)、CSA 1141 准则深度定性
                           │
                           ▼
[机构级数智全景审计舱] ─► 彭博风格暗曜石工作台（经典案例直达、7分钟答辩看点、SVG交互式资金拓扑回路）
                           │
                           ▼
[结构化合规底稿一键导出] ─► Excel 标准工作底稿 (.xlsx，含审定表、调整分录及CPA终审签章)、PDF穿透分析报告、全量JSON
```

### v2.4：职业判断类算子、金额反算、自洽性投票与第三批严格盲测

针对 v2 暴露的漏检（少计费用、减值、预计负债、负债核销），v2.4 做了四件事，均按准则写成通用规则，不含公司名：

1. **职业判断类确定性算子**（`judgment.py`）：服务费已开票却挂预付/其他应收、期末费用转出资本化；期末冲回减值准备、长账龄余额未计提减值；诉讼/担保/赔偿线索而无预计负债；应付转营业外收入且无资金流动；期末预付转其他应收。
2. **金额由账套反算**：模型为每个量化发现声明口径（凭证号 + 科目代码 + 借贷方向），系统在账套中按该口径加总得出金额，模型原报金额保留对照。
3. **中间档定级**：确定性算子未覆盖、但引用单据真实存在、金额可按口径复算且达到执行重要性、并在多次采样中出现≥2 次的判断，最高 MEDIUM；HIGH 仍须确定性算子支撑。
4. **自洽性投票**：同一提示并行采样 3 次（deepseek-flash，reasoning_effort=medium），按引用单据聚类，等级取中位数；修正稿沿用投票结果。进程级并发闸 `DEEPSEEK_MAX_CONCURRENCY`（默认 4）防止 429。

评测纪律：v2 的漏检被用于设计以上改进，因此 v2 自 v2.4 起改标"开发后验证"。另请一位看不到代码、v1、v2 的出题方编写 **v3**（10 家舞弊：乐视网、华锐风电、山东墨龙、广东榕泰、中天能源、紫鑫药业、园城黄金、亚联发展、荃银高科、沈阳化工；6 家合规：五粮液、青岛啤酒、迈瑞医疗、三一重工、顺丰控股、立讯精密；20 条真值），在算法冻结提交之后才首次运行。出题方披露见 `data/cases/blind/AUTHOR_NOTES_v3.md`（部分金额按比例构造；中天能源、园城黄金的决定书原文未完整核验；合规公司的无处罚状态未逐家核验）。

### v2.3：专项实质性程序、重要性与第二批严格盲测

**取舍原则**：采纳能用准则讲清楚、对任何企业都成立的改进；不采纳"照着盲测案例写规则再用同一批案例报高分"的做法——那样的分数没有意义。

**新增确定性算子**（`src/plugins/audit_fraud_plugin/substantive.py`，不含任何公司名或案情关键词）：

| 算子 | 准则依据 | 判断逻辑 |
| :--- | :--- | :--- |
| 重要性水平 | CSA 1221 | 营业收入 × 0.5% 为整体重要性，× 75% 为实际执行的重要性，× 5% 为明显微小错报临界值 |
| 银企账实核对 | CSA 1312 | 银行存款发生额逐笔对对账单（金额 ±0.1%、日期 ±5 天）："有账无流"；存单质押、担保、归集等受限资金线索 |
| 背靠背贸易 | CAS 14 第五条、第三十四条 | 7 天内购销配对、毛利率 −2%～5%、合同约定货权转移不移库/自提/仓单 |
| 截止与成本配比 | CAS 14 第四、十三、三十五条 | 终验类合同按到货/初验在期末确认收入，期后 120 天内出现安装施工付款作反证；已确认收入的发出商品未结转成本 |
| 第三方回款与预付 | CSA 1141、CAS 36 | 冲减应收的回款付款方与账面客户不一致或附言为代付；大额预付期内未结转且付给关联方或无进项发票 |

**口径**：收入类金额一律按主营/其他业务收入贷方**不含税**金额计量，不再用价税合计、也不把同一凭证里的成本结转加进去。

**离线模式去模板化**：原离线引擎按公司名/案情关键词套标题（如"獐子岛"→北斗轨迹），评委一查代码即穿帮。现改为通用规则推理器（`rule_reasoner.py`），只根据算子输出的异常类型和科目口径生成发现项。代价如实披露：开发集通过数从模板拟合的 28/28 回落到 **20/28**（未通过的多为同一事项被拆成多个侧面、或金额口径与开发集真值不一致），3 例合规对照零误报。

**在线模式的三道闸**：
1. **定级校准**：HIGH 必须引用确定性算子检出的异常单据且金额达到实际执行的重要性；只有分录测试风险标识支撑的最高 MEDIUM；没有任何确定性支撑的判断降为 LOW"关注事项"。守卫只调等级并写明原因，不改模型的文字和金额。
2. **自我修正**：证据锚定守卫发现未锚定或金额无法复核时，把问题清单和引用单据的逐行金额反馈给模型重做一轮；只有问题变少才采纳修正稿，两稿都留痕。
3. **补位**：模型没有覆盖到的确定性异常，以"确定性算子生成"标注补入报告。

**新产出**：拟定审计调整分录（AJE，只为锚定到凭证的发现编制，借贷平衡）与审定前后报表冲击（调整额跨期或超过单期报表时明确标注"不可直接相减"）；Excel 底稿新增《拟定审计调整分录》《CSA1131_AI过程记录》两张表，现场签署的注会信息随导出写入，未签署时明确显示"未签署"而非示例姓名。

**第二批严格盲测（v2）**：另一位看不到代码、也看不到 v1 的出题方，依据处罚决定书编写 10 家舞弊公司（贵州百灵、北特科技、德豪润达、如意集团、凯伦股份、林州重机、德威新材、华铭智能、*ST 苏吴、弘高股份）+ 6 家合规对照（宁德时代、中国神华、恒瑞医药、海康威视、万华化学、格力电器）。合规组特意写入复合凭证、凭回单入账的费用、整数广告费、调休日记账等"像异常但正常"的业务。**v2.3 算法冻结并提交后才首次运行，之后不据此调参。**

| 模式 | 舞弊公司被标出 | 真值事项命中 | 金额误差 ≤1% | 合规对照误报 |
| :--- | :---: | :---: | :---: | :---: |
| 离线确定性 | 7/10 | 9/19 | 2/19 | 1/6 |
| DeepSeek 在线（deepseek-flash） | 8/10 | 16/19 | 7/19 | 1/6 |

在线模式下，合规对照组除万华化学一例（三单勾稽检出凭证与发票金额不一致，离线同样报出）外，模型的其余意见全部被校准为 LOW 关注事项，不再出现 v1 时"每家合规公司都有 MEDIUM"的情况。代价同样如实记录：林州重机、华铭智能的真值事项模型其实已经指出（证据锚点命中），但因没有确定性算子支撑被降为 LOW，按"HIGH/MEDIUM 才算标出"的口径记为漏检——定级校准是用一部分查全率换查准率，这些 LOW 级关注事项仍会进入底稿供注册会计师复核。

v2 暴露的真实短板：少计费用、减值不计提、预计负债未确认、应付账款无依据核销等**依赖职业判断**的手法，确定性规则基本覆盖不到（如意集团、林州重机、华铭智能在离线模式下漏检）；金额精确复核率仍低。这正是大模型应当发挥作用、也最需要注册会计师复核的地方。v1 因结果已用于开发，自 v2.3 起只作开发后验证，不再作为盲测引用。

前端同步修正：竞技场改为"开发集 / 盲测 v2 / 盲测 v1 / 合成账套"四页签，全部数字来自现场运行，未运行时显示"待运行"，合规对照显示"零误报通过"；资金拓扑页改为由 `/api/topology/{case_id}` 生成（原先所有舞弊案例共用一张写死坐标的 5 节点闭环图，并读取了真值金额），无资金闭环的案例显示业财单据链；发票列表字段与后端对齐；上传支持第 4 类文件（业务合同台账）；脱敏结果写回案例池并可一键还原。

**外部盲测二：合成随机账套**（`src/benchmark/blind_synthetic.py`）。生成器不导入任何检测代码，节假日按国办全部放假通知（含清明、劳动节、端午、中秋与调休上班日）独立生成；每个账套随机注入正例，并放入"近似但不该报"的负例（调休上班的周末记账、有发票的现销、60 天后才回款或只回款 60% 的资金往来）。20 个种子首次运行发现：检测器只内置了三大节日、且不认调休，导致非工作日规则 Precision 仅 0.22、负例误报率 100%。改用 `chinesecalendar`（国办历年通知）后，6 类规则 Recall/Precision 均为 1.00，Benford 区分"自然金额/编造金额"账套准确率 97.5%。

复现：`uv run python -m src.benchmark.blind_synthetic --seeds 20`；`uv run python -m src.benchmark.blind_real --mode mock`（在线加 `--mode online`）。两项已加入 CI。

> **仍需说明的局限**：盲测案例的凭证、流水仍是出题方依据决定书事实重构的结构化账套，不是企业真实账簿；合成账套的异常形态由生成器定义，满分只说明规则按设计工作，不代表真实世界召回率；开发集 28/28 通过仍属"自建自测"，对外请以盲测数字为准。
